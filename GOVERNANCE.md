# Governance

HolyScreen currently uses a maintainer-led governance model.

The primary maintainer in [MAINTAINERS.md](MAINTAINERS.md) sets project direction,
approves releases, manages security responses, and has final say when consensus
cannot be reached. Contributors influence decisions through issues, discussions,
design proposals, reviews, and pull requests.

Routine changes are decided through pull-request review. Significant changes to
architecture, compatibility, data formats, governance, or user-visible behavior
should begin with a public issue. Security-sensitive decisions may be private.

Only a maintainer may publish a release. Releases should pass CI, include release
notes and checksums, and follow semantic versioning where practical before 1.0.
Participants should disclose relevant conflicts of interest. Governance changes
are made transparently by pull request.
